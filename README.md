# Bybit Screener

Скрининг монет Bybit по волатильности и тренду, торговые планы с уровнями входа/стопа/тейков и бумажный
портфель с лимитными заявками и лесенкой выхода — всё в браузере, без своего сервера.

> ⚠️ Это инструмент для анализа и торговли на свой страх и риск. Никаких гарантий доходности.

## Что доступно

Все функции открыты: скринер, торговые планы, бумажный портфель, подключение ключа Bybit (`/api`),
портфель реального счёта (`/real`) и реальная торговля (`/live`). Ранее `/api` и `/live` были закрыты
заглушками из-за региональных ограничений — блокировка снята, заглушки удалены.

Побочный эффект: на опубликованном GitHub Pages форма ключей и кнопки реальной торговли видны всем.
Ключи при этом остаются в localStorage посетителя — чужих ключей приложение не видит.

## Возможности

- **Скринер**: до 200 монет, ранжирование по «Приоритету» — «куда действительно стоит входить» (уверенность +
  чистота/сила тренда + участие объёма − штрафы за перегрев RSI, растянутую серию и шорты). Быстрый вход
  прямо из таблицы: в режиме «Бумага» — «Вход (бумага)» (лимитная заявка) и «По рынку» (исполнение сразу),
  в режиме «Реально» — «Реальный вход →» (ведёт на форму ордера `/live`, откуда он и отправляется).
  Знак «?» в шапке откроет подробный walkthrough-обзор всех инструментов (можно пропустить и вернуться позже).
- **Торговый план по символу**: EMA20/50, ATR(14), Donchian-20, RSI, наклон/R² → направление, зона входа,
  стоп 1,8×ATR, цели 1R/2R/3R, расклады по всем таймфреймам, график стратегии (чистый SVG).
- **Фильтры качества**: сетап только при R² ≥ 0.5, объём ≥ 0.9 среднего и ATR% ≤ 7; шортам — более высокая планка.
- **Бумажный портфель**: позиции в localStorage, выход лесенкой TP1 70% / TP2 20% / раннер 10% до TP3,
  перенос стопа в безубыток после TP1, честный учёт ликвидации, комиссий и маржи. Кнопка «Закрыть по рынку»
  в таблице. Видно, сколько денег депозита занято в каждой сделке: колонка «Из депозита в сделке»,
  карточки «Занято из депозита» и «Торговый номинал».
- **Ссылка на биржу у каждой пары**: символ в таблице скринера, в портфеле, в заголовке плана и
  разбора позиции, в позициях/ордерах/исполнениях реального счёта — кликабельный: открывает торговлю
  этой пары на Bybit в новой вкладке. Клик по остальной части строки по-прежнему открывает план.
  Для опционов и нестандартных спотов пар ссылка не рисуется — на Bybit их нет в нужном виде.
- **Вход по рынку** (по желанию): кнопка «По рынку» открывает позицию сразу по текущей цене, без
  ожидания отката. Размер считается от фактической дистанции до стопа, поэтому риск в $ тот же,
  а соотношение риск/прибыль хуже, чем у лимитного входа по зоне; проскальзывание в бумаге не
  учитывается — в интерфейсе про это написано прямо.
- **Портфельный лимит**: задействованный капитал (сумма марж открытых позиций) не может превышать депозит.
- **Подключение API Bybit** (`/api`): ключ и секрет в localStorage, подпись HMAC-SHA256 в браузере, проверка
  баланса и позиций. При локальной работе ключи можно не вводить руками — положить в `.env`.
- **Режим «Бумага ⇄ Реально»** в шапке: один переключатель решает, что делают кнопки входа, а полоса под
  шапкой всегда показывает, где вы сейчас и в какой сети. Реальный ордер отправляется только со страницы
  `/live` и только после подтверждения — из таблицы деньги не тратятся.
- **Портфель реального счёта** (`/real`): когда API подключён, здесь капитал, занятая маржа, позиции и
  висящие ордера прямо с биржи — живьём по WebSocket (REST остаётся страховкой). Шапка в реальном режиме
  (и на `/real`) тоже показывает реальный счёт, в бумажном — бумажный портфель.
- **Реальная торговля** (`/live`): план → ордер, лесенка TP1/2/3, стоп в безубыток, закрытие по рынку,
  лента свежих исполнений.
- **Аналитика бумажного портфеля** (`/paper`): срезы по закрытым (направление, уверенность, ATR, таймфрейм,
  исход) + кривая доходности — видно, где стратегия реально зарабатывает, а где только кажется.
- **Журнал сигналов**: скринер пишет снимки своих сетапов, чтобы можно было сверить «что показал,
  что взял, как отработало».
- **Защита от «margin call раньше стопа»**: вход блокируется, если при выбранном плече ликвидация ближе
  стопа (стоп занимает ≤70% пути до ликвидации).
- **Бэктест-стенд** (`bun scripts/backtest.mjs`): честная проверка стратегии — вход только если зона реально
  задета, комиссии/слип/фандинг, порог уверенности как в приложении, отчёт по четвертям истории и сравнимые
  прогоны на фиксированном универсуме (`scripts/universe.json`).
- **Установка как приложение** (PWA): кнопка «Установить» в шапке (на iOS — инструкция для Safari).
  Приложение открывается отдельным окном, работает без адресной строки и переживает отсутствие сети:
  в офлайне доступна последняя загруженная страница, а котировки и свечи Bybit — нет (это осознанно:
  старые цены в приложении опаснее, чем честная ошибка загрузки).

## Быстрый старт

```sh
bun install
bun run dev        # http://localhost:5173 (прокси /bybit)
bun run build      # прод-сборка в dist/
bun run preview    # предпросмотр сборки
```

Ключи Bybit для локальной работы (необязательно — их можно ввести руками на `/api`):

```sh
cp .env.example .env
# вписать API_KEY и API_SECRET; API_TESTNET=1 — переключение на тестнет
```

`.env` подхватывает **только dev-сервер**: в `bun run build` значения пустые, поэтому секреты физически
не попадают в `dist/`. Сам `.env` в `.gitignore`, в репозитории лежит только `.env.example`.

Тесты и линт:

```sh
bun run test       # vitest (юнит-тесты) — именно через bun run, не bun test
bun run test:watch
bun run lint       # oxlint
```

Бэктест стратегии по истории (walk-forward, 5m):

```sh
bun scripts/backtest.mjs [SYMBOL ...]
```

Иконки приложения (PWA) генерируются скриптом — вручную ничего править не нужно:

```sh
bun scripts/gen-icons.mjs   # перерисует public/icons/*.png
```

PWA (манифест, service worker, установка) работает только в прод-сборке: в `bun run dev` воркер
не регистрируется, иначе кэшировал бы модули Vite и ломал бы HMR. Проверять через
`bun run build && bun run preview`.

## Бумага или реальные деньги

В шапке есть переключатель **«Режим: Бумага ⇄ Реально»**, а под шапкой — полоса, которая всегда
показывает, где вы сейчас:

| Режим | Кнопка входа в скринере | Кнопка входа в плане символа | Портфель в шапке | Куда уходят ордера |
|---|---|---|---|---|
| **Бумага** (по умолчанию) | «Вход (бумага)» — виртуальная лимитная заявка, «По рынку» — сразу по цене | «Открыть (бумага)» и «По рынку» | бумажный P&L, `/paper` | никуда, деньги не двигаются |
| **Реально** | «Реальный вход →» / «Реальный →» — открывает форму ордера | «Реальный ордер →» | реальный счёт Bybit, `/real` | только с `/live` и только после подтверждения |

Ключевые правила:

- реальный ордер **никогда** не отправляется из таблицы или плана — кнопка лишь приводит на `/live`,
  где риск и плечо уже перенесены из общих настроек сессии, а отправка требует галочки «реальные деньги»
  на мейннете;
- включение реального режима спрашивает подтверждение (своё окно в приложении, не системный диалог),
  по умолчанию всегда бумажный;
- на `/live` и `/real` переключатель заменён красной меткой «Реальные деньги» — там всё настоящее;
- режим живёт в `sessionStorage` вкладки (`trade:mode`), то есть переживает перезагрузку страницы.

## Как читать деньги в портфеле

Депозит занимается **маржой**, а не номиналом. Маржа позиции = номинал / плечо:

- «Ставка 1000 $ × плечо 20» — это потолок суммарной маржи и множитель, а не 20 000 $ в сделке;
- в сделке заблокировано столько, сколько показывает колонка «Из депозита в сделке» (в прошлой сессии —
  47…231 $ на позицию, средняя 106 $ при депозите 1000 $);
- торговый номинал в разы больше маржи — это объём сделки, а не твои деньги;
- сумма марж открытых позиций не может превысить депозит (портфельный лимит), поэтому
  «20 позиций × 1000 $» невозможно: при плече ×20, стопе 1.4 % и риске 3 % позиций будет ≈9.

## Как работает стратегия

План строится в браузере по 200 свечам (минимум 55):

- направление: цена относительно EMA20/EMA50 + наклон и чистота тренда (R²), RSI, импульс, объём;
- вход — лимитная заявка по середине зоны между ценой и EMA20 (покупка отката), стоп 1,8×ATR от нижней
  границы зоны, цели 1R/2R/3R;
- уверенность (8..96) — непрерывная оценка качества сетапа;
- качественные фильтры отсекают шум: слабый тренд, мёртвый объём, ураганную волатильность;
- кнопка «Вход» в скринере выставляет бумажную лимитную заявку по середине зоны (размер из риска,
  плечо и ставка — из общих настроек сессии).

Бумажный вход — такая же лимитная заявка, как настоящий ордер на бирже: пока цена до лимита не дошла,
позиции нет и P&L нулевой («Лимит в рынке» в портфеле), неисполненная заявка снимается вручную или сама
через 24 часа. Бумажный выход — лесенка: TP1 фиксирует 70% позиции, TP2 — ещё 20%, раннер 10% едет до TP3;
после TP1 стоп переносится в безубыток. Стоп, безубыток и TP3 закрывают остаток. Открытые позиции
переоцениваются по живым ценам, комиссия учитывается за круг.

## Реальная торговля

1. Создай API-ключи Bybit V5 (для отладки удобнее **testnet.bybit.com**).
2. Вставь их на странице `/api` (сеть **Тестнет**) → «Сохранить и проверить». Либо положи ключи в `.env`
   при локальной работе — тогда форма подставит их сама и проверит подключение.
3. Открой `/live`, введи символ и таймфрейм — живой план → «Открыть ордер».

Что делает движок (всё по плану, как в бумажном режиме):

- устанавливает плечо;
- ставит лимитный вход по середине зоны со стопом (триггер — MarkPrice);
- вешает лесенку: reduce-only лимитки TP1/TP2/TP3;
- по кнопке закрывает по рынку и переносит стоп в безубыток.

Подпись запросов — HMAC-SHA256 прямо в браузере (CORS Bybit это разрешает), сервер не нужен. Движок живёт,
пока вкладка `/live` открыта.

### Проверка подключения к мейннету (без внесения денег)

27.09.2026 ключ мейннета проверен на живых ответах биржи (баланс счёта 0 $ ⇒ ни один ордер не мог
исполниться, вход отклоняется `110007`):

| Проверка | Результат |
|---|---|
| `wallet-balance` (подпись, ключ, recv_window) | ✅ `retCode 0`, equity 0 $ |
| `position/list`, `order/realtime`, `instruments-info` | ✅ после фикса `settleCoin` |
| `set-leverage`, `order/cancel-all` | ✅ `retCode 0` (плечо возвращено к ×10) |
| `position/trading-stop` без позиции | ✅ ожидаемая бизнес-ошибка `10001` |
| неверный секрет | ✅ `10004` с подсказкой про ключ/время |
| `openReal` целиком | ✅ дошёл до биржи, отказ по балансу `110007` |
| `closeReal` / безубыток без позиции | ✅ `110017` / `10001`, страница не падает |

Найдено и исправлено два бага: `order/realtime` и `order/cancel-all` без `symbol` возвращали `10001` —
Bybit требует `settleCoin` (для spot — `baseCoin`). Полный журнал retCode и сценарий — в локальном файле
`SESSION-MAINNET.md` (в репозиторий не коммитится).

Реальное исполнение (срабатывание SL, лесенка, авто-перенос в безубыток) без денег проверить нельзя:
нужен ненулевой баланс. Для **полномасштабной** сессии (несколько одновременных позиций, риск 1–2 % на
сделку) минимум — ~$1000, комфортно ~$1500 (при курсе 84.3 ₽/$ это 84 000 ₽ и ~126 000 ₽); число
одновременных позиций от депозита не зависит — ≈9 при риске 3 % и плече ×20. **Первый реальный тест
такого размера не требует** — хватает депозита 100–200 $ (см. ниже): один-два цикла «вход → TP1 →
безубыток → закрытие», чтобы проверить, что биржа принимает ордера и лесенку, а не чтобы заработать.

### Минимальный депозит для первого теста

Размер позиции считается от риска: `qty = риск $ / дистанция до стопа`. Но у биржи есть минимум на
**каждую заявку**: у Bybit это ~5 $ (`minNotionalValue`; в API поле часто пустое, поэтому движок
подставляет дефолт 5 $ для linear/inverse). Раннер — это 10 % позиции и отдельный ордер, значит
позиция должна быть ≥ 10 × 5 = **50 $**, а срезы ещё и округляются вниз по шагу количества.

Измерено по реальным инструментам (29.09.2026, стоп 1.8 %):

| Символ | Цена | Шаг qty | Мин. позиция | Мин. риск | Депозит при риске 1 % / 2 % |
|---|---|---|---|---|---|
| WIFUSDT | 0.2416 | 1 | 51 $ | 0.91 $ | 91 $ / 46 $ |
| DOGEUSDT | 0.09587 | 1 | 51 $ | 0.91 $ | 91 $ / 46 $ |
| ARBUSDT | 0.21209 | 0.1 | 50 $ | 0.90 $ | 90 $ / 45 $ |
| SOLUSDT | 120.96 | 0.1 | 121 $ | 2.18 $ | 218 $ / 109 $ |
| ETHUSDT | 2731.25 | 0.01 | 273 $ | 4.92 $ | 492 $ / 246 $ |
| BTCUSDT | 84 212 | 0.001 | **842 $** | 15.16 $ | 1516 $ / 758 $ |

Выводы:

- **BTCUSDT и ETHUSDT для микро-теста не годятся** — мелкий шаг количества съедает номинал:
  раннер в 10 % должен быть ≥ 1 шаг, то есть 85 $ / 27 $; плюс мин. позиция 273 $/842 $ выше
  депозита 200 $.
- Дёшево и гладко — альты с шагом 1 шт: минимальная позиция ~50 $, минимальный риск ~0.9 $.
  SOLUSDT (шаг 0.1) тоже проходит: мин. позиция 121 $, мин. риск 2.18 $ — на депозите 200 $
  это риск от 1.1 %.
- Практический первый тест: **депозит до 200 $ (рекомендация 100–200 $)**, риск 1–2 %, **плечо ×5**.
  При 200 $ и риске 2 % (4 $) позиция ~218–222 $, маржа ~44 $ — лесенка проходит у
  WIF/DOGE/ARB/SOL. При риске 1 % (2 $) SOL теряет TP3 (срез ~12 $ < минимума 5 $ уходит в 0) —
  для SOL держать риск ≥ 2 %. При ×20 маржа позиции 2.5–5 $, ликвидация в 4.5 % от входа,
  и проскок по MarkPrice съедает P&L раньше стопа.
- Маржа не ограничивает: 50 $ / 5 = 10 $ маржи, а лимит депозита упирается в риск, а не в номинал.
- Страница `/live` считает этот минимум сама и показывает строку «Минимум для лесенки» **до** отправки
  ордеров; если риск мал — кнопка «Открыть ордер» заблокирована с объяснением (какой срез не проходит
  и какой риск нужен). Это защищает от классической ошибки: вход прошёл, а TP3 отклонился биржей
  и позиция осталась без выходов.

### Безопасность

- Секрет API хранится только в localStorage браузера или в локальном `.env` — никогда не выкладывай его
  в код/репозиторий. `.env` в `.gitignore`, в репозитории только `.env.example`.
- Для **мейннета** используй ключ **без права вывода** и с ограничением по IP; начинай с тестнета.
  Мейннет-действия требуют явного подтверждения в интерфейсе.
- GitHub Pages — статический хостинг: скрипты видны всем, но ключ остаётся в твоём браузере.
- Движок не оставит позицию без выходов: перед отправкой он проверяет, что вход и все три TP проходят
  биржевые минимумы, а если TP не выставился — отменяет вход и уже поставленные заявки.

Как распределялись деньги депозита: маржа позиции 47–231 $ (средняя 106 $), пиковая одновременная маржа
992 $ (это лимит приложения — сумма марж ≤ депозита), суммарный торговый номинал 35 951 $, риск на сделку
30 $ (3 % депозита), средний стоп 1.82 %.

Честный вывод: плюс обеспечен в основном TP1 с переносом стопа в безубыток (9 сделок) и одним раннером
до TP3. Бумажный портфель не реинвестирует прибыль, а выборка в 17 сделок ничего статистически не
доказывает — сессия проверяла механику, а не стратегию.

Реально сработавшие ограничения входа: «Задействованный капитал исчерпан» (свободно 8–77 $),
«Не хватает маржи: нужно 3484.10 $ при ×20», «Ликвидация ближе стопа: максимально безопасное плечо ~×9».
